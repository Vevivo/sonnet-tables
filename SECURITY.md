# Security

Do not publish private keys, encrypted vaults, passwords, access tokens or database exports in an issue, pull request or screenshot.

For an exploitable vulnerability, use GitHub's private vulnerability reporting if it is enabled for this repository. Otherwise ask the maintainer for a private reporting channel without posting exploit details publicly.

The browser can prepare signatures with an existing identity. Private keys stay in tab memory; the backend receives signed messages. All signed contest messages are intended for public rooms. Review the payload before submitting it.

The repository includes configuration examples, not production credentials. Public API origins and referee DIDs are not secrets. If a credential is accidentally exposed, revoke or rotate it; removing the file from the latest commit is not enough.
